## PDF 目录提取测试（kids-knowledge-base）
- 资源 `resources/2025秋7星学霸题中题数学4年级第7辑.pdf`（130MB, 162 页）实测为**纯扫描图版 PDF**：每页 1 个 Image 对象、0 个 Font，**无任何文本层**。
- 纯 PDF 文本解析 + 关键字匹配（`extract_toc.py`，pypdf）实测：162 页文本长度全 0，命中「目录」0 页，目录候选页 0。结论：纯解析在此文件上**做不到**定位目录页。
- OCR 路线已落地跑通。依赖用 uv 装进**本目录 `.venv`**（用户规范：项目依赖统一在 `.venv`，pyproject.toml 声明 `pymupdf>=1.28.2` + `rapidocr-onnxruntime>=1.4.4`，`uv sync` 跨平台复现）。安装时 WorkBuddy 沙箱内存限制会 OOM 杀进程（exit 137），需 `dangerouslyDisableSandbox` 放开跑（用宿主内存）。
- `extract_toc_ocr.py`（fitz 渲染 dpi200 + RapidOCR 识别）实测：扫前 40 页约 47s，精准定位**目录页=第5页（strong）**，第8/10页 weak 误报（正文含「第X讲」+数字行）。`extract_toc_entries.py` 把 OCR 行配对成「第X讲+题名+页码」输出 `toc_entries.md`：16讲全提取，第2~16讲页码清晰（10~148），**第1讲页码 OCR 未识别**（引导点+页码被吞，可 dpi300 重跑该页或按 bbox 坐标合并优化）。
- 教训：本机非交互 shell 用绝对路径 `/opt/miniconda3/bin/uv` 命中（.zshenv 已注入 PATH）；装大包优先 uv 而非 pip（省内存）；沙箱装 pymupdf/opencv 等 C 扩展包务必 `dangerouslyDisableSandbox`。
- 回应原始问题「纯解析能否找到目录页」：**不能**（无文本层）；OCR（fitz+rapidocr，纯 Python 跨平台）**能**，第5页即目录。
- OCR 选型结论（用户问轻量 OCR）：PaddleOCR 太重（带 PaddlePaddle 框架，~450MB 内存），不推荐。轻量候选：① RapidOCR(rapidocr_onnxruntime) 纯 pip、onnxruntime 后端、中文~98.7%、首次跑需联网下 ModelScope 模型；② macOS 原生 Apple Vision/Live Text（pyobjc 调 VNRecognizeTextRequest）零模型下载、质量高速度快，最轻；③ Tesseract chi_sim（brew）依赖最少但中文精度~92%。渲染器用 pymupdf 或 macOS 原生 sips/qlmanage，只需渲染前~20页。

## 扫描 PDF 转 Markdown 咨询
- 结论：扫描图版 PDF **不存在"直接"转 markdown**（无文本层，必须 OCR+版面分析）。成熟一键路线：① **MinerU**（OpenDataLab，最对位中文教辅：自动 OCR+公式LaTeX+表格HTML+标题层级，pip 装、跨平台、Apple Silicon 走 MPS）；② Marker（快但表格/公式/中文弱于 MinerU，GPL/研究许可）；③ Docling（IBM，跨平台 CPU 可跑但中文一般）；④ 视觉模型路线（竖式/思维导图最准，需 API/本地 VLM）。排除 MarkItDown / PyMuPDF4LLM（无 OCR）。
- **MinerU 是开源项目（GitHub opendatalab/MinerU，Public，58.5k+ stars），许可证 AGPL-3.0（强 copyleft）**：本地自用/内部处理无碍；仅"改源码分发"或"作网络服务对外提供"需合规。代价：依赖重（torch/detectron2 类）、首次下模型、纯 CPU 推理慢。资源：pipeline 模式官方内存≥16GB（实战 8GB 可跑但慢）、磁盘≥20GB 装模型、纯 CPU 可跑；VLM 高质量模式需 GPU（6~24GB VRAM 视后端）；Apple Silicon 走 MPS 加速。教辅竖式/思维导图所有工具都会部分崩，需人工校对。安装须 `dangerouslyDisableSandbox`（沙箱 OOM 杀大包）。
- **用户实际问的 OCR 工具是 github.com/baidu/Unlimited-OCR（非上轮猜的 whit3rabbit/unlocr）**：百度 2026-06 开源，MIT 许可（比 MinerU 的 AGPL 宽松得多，可商用/改/闭源）。3B VLM（MoE，激活~570M），基于 DeepSeek-OCR 架构，端到端 页面图→Markdown/HTML(表格)/LaTeX(公式)+bbox。核心创新 R-SWA：KV 缓存恒定，可一次前向吃几十页（跨页表格/阅读序天然保留），OmniDocBench v1.6 综合 93.92%（端到端第一档）。资源：全精度 BF16 权重~6.78GB；官方主路径 transformers/vLLM/SGLang 写 `.cuda()`（要 NVIDIA）；但**明确提供 MLX 8-bit 量化专为 Apple Silicon Mac 原生优化**、GGUF(2~5GB 纯 CPU)、NVFP4。推荐 16GB 统一内存 Mac 或 12GB+ 显存 GPU。对比 MinerU：单模型更轻(2~7GB vs 20GB)、Mac 原生(MLX vs MPS)、一次多页(免拼接)、竖式/思维导图 VLM 读整体更稳、MIT 无合规包袱；代价是"40页一次过"在 16GB Mac 上未必塞满、且只做文档 OCR 非通用场景识别。针对本机 Mac+中文扫描教辅，Unlimited-OCR(MLX) 比 MinerU 更对路。
