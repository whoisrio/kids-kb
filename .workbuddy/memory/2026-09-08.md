设计要点（写入文案/UI 的硬决策）：
- bbox 三态语义：灰细=正常，蓝实=当前聚焦（跟随列表/悬浮/键盘），红实=问题（低置信/规则命中），琥珀=人工已改。**红色只表示有问题**，聚焦态不和错误色撞车。
- 质检规则写成可配表（块置信<0.6 / VLM 评分<0.80 / 文本密度 / 乱码率 / 题号序列 / 抽样比例），判定逻辑不藏在 UI 里。
- 顺序：OCR→VLM补→VLM质→人工→LLM抽题→人工确认题→向量入库。**VLM 补解析结果不能再由 VLM 自评**，强制进人工队列（屏幕有 callout 强调）。
- 向量化是「发布」动作可重跑：chunk 带 `source_id + revision`，题目改动 → revision+1 → 旧向量标失效待重建。入库粒度默认「题组（材料+子题）」，单题做子块保留父引用。
- 入库前的人工题目复核提供「缺图题」提示和「关联题组」操作。
- 左队列底部「抽样复核 10% 随机页」+ 说明「规则命中页必审 + 随机抽样，其余自动通过」，降低逐页全审成本。

复用既有术语：自动审核 pending/passed/needs_review/failed，人工 unreviewed/approved/rejected，索引 not_indexed/indexed/stale；流水线 6 阶段徽章用色一致（done=绿、warn=琥珀、active=主色蓝、idle=灰虚）。

## 追加需求：题目 chunk 分问答 + 图形裁图（核实结论，待用户决策）

核实到的 schema 事实（pipeline/kb/migrations/0001_init.sql、0008_chunks.sql；kb/embed.py）：
- `item_blocks.role ∈ (stem, figure, solution)` —— 题干/图/解答**已经分角色**绑定 item，不是缺能力。
- `blocks` 已有 `bbox jsonb` + `crop_path text NOT NULL` + `block_type ∈ (page,text,formula,figure,table,header,footer)` —— **按 OCR 块裁图的能力已经存在**，用户说的"应该可以保留图像"其实是已有功能未接进 md/呈现。
- `chunks.item_id UNIQUE` + `item_embeddings.item_id PRIMARY KEY` —— **一个 item 只有一个向量**。
- `embed.py` 输入是整条 `items.content_md`（stem 与 solution 混在一起喂模型），**没有区分问答**。

我的反驳与建议（尚未落地）：
1. 答案**不能**单独成可检索 chunk：query 与答案文本语义距离远，检索不到；检索到也是无头答案。`chunks.item_id UNIQUE` 也挡着，改要动 schema。建议：一个 chunk = 一道题（stem+solution 同块），**embedding 只喂 stem**，solution 作为 payload 不参与 embedding。
2. "非 LaTeX 能画出来的图"这个划分标准不可执行——无法自动判定。可执行标准是 `block_type='figure'` + 块内可提取文本占比低。
3. 硬坑：裁出的图不进文本向量 → 图里才有数据的题检索不到。必须由 VLM 生成图片描述文本并作为 stem 一部分参与 embedding。
4. md 里图片引用别写物理相对路径（storage/ 下 md 是只写镜像，重跑/迁移会断），应存逻辑引用（block_id 占位），渲染时 JOIN `blocks.crop_path` 出 URL。
5. bbox 紧贴直接裁会切掉边框和图注，crop 要外扩 padding；同一张图被题组多子题引用要去重。

待用户回答的关键问题：答案要不要独立成可检索 chunk，还是只挂在题目 chunk 里当字段。

- DPI 默认 200（config.py:18）。

### padding 结论（已写进 spec）
按**物理长度**定义（改 DPI 不用改配置）：text 0.8mm 横/0.5mm 纵，figure 1.5mm 横/1.0mm 纵。
纵向比横向保守是因块间距纵向更小（填空题连排行距 200DPI 下仅 8–16px）。
A4@200DPI 实际值：text 6px/4px（归一化 x:4 y:2），figure 12px/8px（归一化 x:7 y:3）。
三条 clamp：① `& page.rect` 边界（_crop_question 要补）；② 与相邻块不重叠（pad = min(pad, gap/2)）；③ **bbox 存原始值，padding 只在裁图时加**（实际生效量记 `blocks.crop_pad`），否则人工调框后反查坐标不一致。

### 相对路径基准（用户决定，我给了风险处置）
基准 = `KB_STORAGE_DIR`（pipeline/storage/），md 里写 `![](blocks/<page_id>/b007.png)`。
必须同时改两处后端否则读不出：`review.ts:23` 的 dirname(storageRoot)→storageRoot；`paperQuestions.ts:137` 改走 resolveStoragePath。
代价：export 必须整目录搬（md + blocks/ + pages/ 一起），单独拷 md 链接会断，已写进 spec 风险项。

## paddleocr layout extra 装机可行性核实（Apple M5 / macOS 26.6 / py3.13）

起因：`kb/layout.py` 的 `from paddleocr import LayoutDetection` 报 ModuleNotFoundError。

### 已核实的事实（不用再查）
- `.venv` 没装 paddleocr，原因**不是包有问题**，是它在 `pyproject.toml` 的 `[project.optional-dependencies] layout` 下，`uv sync` 默认不装。要 `uv sync --extra layout`。
- `uv.lock` 早就锁好了：paddleocr 3.7.0 + paddlex 3.7.2 + paddlepaddle 3.3.1。所以之前有人带 extra sync 过，现 venv 是没带 extra 装出来的。
- ~~这段代码默认是死代码~~ **此条已证伪，见 2026-09-09 更正**：`.env` 里 `KB_LAYOUT_ENGINE=paddleocr`（第 10 行），`make_layout_analyzer()` 实测返回 `PaddleOCRLayout`，跑管线会**真的崩**，不是死代码。
  - 教训：`.env` 的键名是**大写**（`KB_LAYOUT_ENGINE`），用 `grep "layout_engine"` 小写去搜会漏匹配，得出"未设置"的错误结论。查 env 务必大小写不敏感或先列全部键名。
- `from paddleocr import LayoutDetection` 写法正确 —— 扒了 paddleocr 3.7.0 wheel 的 `__init__.py`，第 22 行 import、第 97 行 `__all__` 均有。
- `PP-DocLayoutV2` 模型名**仍然有效** —— paddlex 3.7.2 wheel 里有 `configs/modules/layout_detection/PP-DocLayoutV2.yaml`（V3 并存于 layout_analysis/）。不用担心被 V3 顶掉。
- 版本兼容：paddlex 要求 `numpy<2.4,>=1.24`，venv 是 2.3.5 ✓；`opencv-contrib-python==4.10.0.84` 有 macosx_11_0_arm64 wheel ✓；paddlepaddle 3.3.1 有 `cp313-cp313-macosx_11_0_arm64` wheel（104MB）✓。
- `uv sync --extra layout` 会装 **72 个包**。其中跟版面检测无关的有一堆：premailer/cssutils/encutils（HTML 邮件样式）、tiktoken/tokenizers/sentencepiece/safetensors（VLM 文本侧，本项目走 rapidocr+视觉模型用不上）、bce-python-sdk/aistudio-sdk（百度云下载）、pandas/scikit-learn/scipy（paddlex 核心）。

### 未验证 / 真风险
- **paddlepaddle 官方 install 文档通篇不提 macOS**，只讲 Linux Docker 和 pip CPU/CUDA。macOS arm64 有 wheel 但不在官方支持叙事里。
- M5 是新芯片，paddle 的 CPU 探测（会被拉进来的 py-cpuinfo）可能翻车。
- README 写的"Mac CPU 353s/页""PP-DocLayoutV2 ~5s/页"说明这条路径在项目里真在 Mac 上跑通过，但不确认是不是 M5。
- 验证姿势：先 `uv sync --extra layout`，再单独 `uv run python -c "import paddle; paddle.utils.run_check()"`，**别一上来就跑管线**。

### 备选方案（paddle 在 M5 翻车时）
