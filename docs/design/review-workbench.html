入库

入库 = 生成 chunk + 向量。它是一次可重跑的「发布」动作，不是一次性写入； 题目改动 → revision +1 → 旧向量标记失效 → 重建。

分块修正 · OCR 切错了怎么改

分块错了有四种情况，处置成本差别很大：改文字 / 合并 / 按行拆分不动 bbox，即时生效； 调框 / 补画动了 bbox，必须重裁 + 重跑 OCR，要等模型。 这条链的因果是 bbox → 裁图 → OCR → content_md，动上游就必须重跑下游。

答案关联 · 卷末答案区

答案不单独成 chunk，只作为题目 chunk 里的独立字段。卷末统一给答案时，解析阶段就要把它拆开并按题号对回题目—— 对不上的进人工，不能靠位置相邻猜。

④ 题号对齐：拿切出来的题号去匹配题目 item 的 label，匹配不上进人工。

为什么不能靠位置

答案在卷末，和题目隔着好几页，「下一个块就是答案」这个假设直接失效。 现有 pair_items() 是按 label 精确相等配对的—— 连排答案切不出来、题号写成「9、」还是「9.」不一致，都会静默漏配。

    二、入库与重建

    • · chunk 与题目/页强绑定，带 source_id + revision。
    • · 人工改动题目 → revision +1 → 对应 chunk 标记 索引过期，旧向量在重建前不参与检索。
    • · 默认入库粒度为题组（材料 + 子题），单题做子块并保留父引用。
    • · 向量化可整卷重跑，也可单 chunk / 单题重建。
    • · 图形块暂不进向量，只在 chunk 里留 figure: 描述 占位，缺图题在拆题复核里提示补录。
