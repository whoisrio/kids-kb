# 扫描版学习资料 PDF 结构化解析流水线 — 设计文档

日期：2026-08-31
状态：待评审

## 1. 背景与目标

resources/ 下的学习资料（《7星学霸题中题》、《学霸提优大试卷》、《寒假计算大通关》等）全部是扫描图片型 PDF，无文本层。
内容不只是习题，还包含例题精讲、思维导图、答案解析等多种版面。
数学题（竖式谜、图形题）对解析精度要求极高，现有尝试（Unlimited-OCR、本地 qwen3.5:4b、远端 qwen3）证明单靠整页 VLM 转录无法满足。

目标：把这些 PDF 解析成**结构化、可检索、文本准确**的知识库，按科目/分类归档例题讲解，按试卷归档试题。
规模：大几千页且持续增长，人工只能抽查，质量保障以自动化检测 + 按置信度分流为主。

## 2. 核心设计决策

1. **文本必须准确**：解析结果用于 LLM 讲题等下游，数学内容不能错。
2. **本地优先、复杂升级**：常规内容本地解析；公式/竖式/图形等硬区域升级远端强模型，只为硬区域付费。
3. **原图兜底**：每个版面区块的裁图一律存档，作为 ground truth；解析错了数据不丢，模型升级后可只重跑解析。
4. **混合检索**：结构化字段过滤为主，向量召回为辅，数学内容不指望向量单挑。
5. **分类体系从目录学习**：taxonomy/tags 从每本书的目录页抽出封闭词表，结构化时让 LLM 从词表选择，防止标签发散。

## 3. 流水线架构（五阶段）

每阶段输入输出落库，可独立重跑、断点续跑。

```
PDF → ①渲染 → ②版面分析 → ③分区域解析(分级) → ④结构化拆分 → ⑤质检分流
        ↓         ↓            ↓                   ↓            ↓
     页面图    区块+坐标    块级内容+裁图       条目JSON    自动过/复核队列
```

### ① 渲染

PyMuPDF 渲染每页为图片（~200dpi），页面图存档。
同时检测文本层（现有 has_text_layer.py），有文本层的 PDF 走更便宜的直读路径。

### ② 版面分析

首选 PaddleOCR-VL-1.5（两阶段：版面检测 + 逐元素识别，0.9B，Mac最值得期待可跑，Apache 2.0）。
输出每页的区块列表：类型（标题/正文/公式/竖式图/表格/页眉页脚等）+ 坐标 bbox。
该阶段是整条流水线的地基，落地时用黄金集实测；不达标则备选 MinerU 2.5 或让远端 VLM 做带坐标的版面分析。
接口设计为可插拔（LayoutAnalyzer），换引擎不动其他阶段。

### ③ 分区域解析（分级）

- 纯文本区块 → rapidocr（现有依赖，本地，快）。
- 公式/竖式/思维导图等硬区块 → 远端强模型（Qwen3-VL-Max，备选 Mathpix）按裁剪图解析，输出 LaTeX + 自然语言描述。
- 所有区块无论解析成败都裁图存档（ground truth）。
- 单区块失败只记录不中断，进入质检视野。

### ④ 结构化拆分

远端纯文本 LLM（便宜，不吃图）读组装好的页面 markdown，拆出条目：
- `example`（例题讲解）、`exercise`（试题）、`answer`（答案解析）。
- 打标签：科目/讲次/题型/难度/特殊标签，taxonomy 和 tags 从该书的目录词表中选。
- 条目关联其来源区块（题干/配图/解析）。
- 试题类条目按试卷组织（章节为空，用题号）；例题类按章节/分类组织。

### ⑤ 质检分流

自动检查：LaTeX 可编译性、题号连续性、抽样双模型比对。
产出条目级置信分：高置信直接入库，低置信进复核队列。
复核界面前期用导出清单，后期做本地 web 页（裁图与解析文本并排）。

## 4. 引擎选型与对比

候选：PaddleOCR-VL-1.5 / MinerU 2.5 / Unlimited-OCR（百度）。

- PaddleOCR-VL-1.5：两阶段（版面检测+0.9B VLM 识别），OmniDocBench v1.5 约 94.5%，SOTA；轻量，Mac 上最可行；Apache 2.0。
- MinerU 2.5：端到端 1.2B VLM，同分档，表格专项最强（Pro 版 TEDS 91.1）；部署重，官方主推 GPU；AGPL。
- Unlimited-OCR：端到端 3B MoE（激活 0.5B），OmniDocBench v1.5 约 93.2%；长文档恒定显存；MIT；但版式语义弱于两阶段方案，且 MLX 裸推理有重复循环问题（本项目已踩坑）。

选择 PaddleOCR-VL-1.5 的理由：架构与"版面切块→分区域处理"原生匹配；Mac 部署成本最低；三者 benchmark 差距小，共同的数学弱项由"硬区域升级远端"兜底，不是选型决定因素。

参考：[PaddleOCR-VL-1.5](https://arxiv.org/html/2601.21957v1)、[MinerU2.5-Pro 对比](https://arxiv.org/pdf/2604.04771)、[Unlimited OCR](https://arxiv.org/html/2606.23050v1)。

## 5. 模型与基础设施清单（选型定案）

| 环节 | 选型 | 运行位置 | 备注/备选 |
|---|---|---|---|
| 渲染 + 文本层检测 | PyMuPDF（已装） | 本地 | ~200dpi |
| 版面分析 | PaddleOCR-VL-1.5（HuggingFace `PaddlePaddle/PaddleOCR-VL-1.5`） | 本地（Mac CPU/MPS） | 黄金集实测不达标则换：MinerU 2.5 / 远端 VLM 带坐标解析 |
| 纯文本区块 OCR | rapidocr-onnxruntime（已装） | 本地 | |
| 硬区域解析（公式/竖式/图形） | 阿里云百炼 DashScope `qwen3-vl-max` | 远端 API | 备选 Mathpix；复用现有 .env 里的远端渠道配置 |
| 结构化拆分 | 阿里云百炼 DashScope `qwen-plus` | 远端 API | 纯文本任务；备选 qwen-flash |
| Embedding | bge-m3（fastembed 加载） | 本地 | 1024 维，中文检索效果好的开源模型 |
| 数据库 | PostgreSQL（本地已有实例）+ pgvector 扩展 | 本地 | schema 用 SQL migration 文件管理 |

新增依赖：`paddlepaddle`（Mac arm64 CPU 版）、`fastembed`、`psycopg[binary]`、`pgvector`（Python 驱动侧）；百炼走现有 openai 兼容客户端。
所有模型名/端点集中在配置里，换模型不改代码。

## 6. 存储设计（PostgreSQL + pgvector）

本地 pg 服务，向量用 pgvector，结构化过滤与向量召回在同一条 SQL 混合。

### documents（资料）

书名、科目、年级、学期册别、教材版本（人教/北师大）、`doc_type`（workbook 习题集 / exam 试卷）、页数、解析状态（断点续跑用）。

### pages（页面）

所属文档、物理页码、页面图路径、版面分析状态。

### blocks（版面区块，证据/回溯层，不建向量）

所属页、类型（标题/正文/公式/竖式图/表格/页眉页脚等）、bbox、裁图路径、解析文本、置信分。
页眉页脚等装饰块不属于任何 item，只留在本表。

### items（条目，检索单元，建向量）

- `content_type`：example 例题讲解 / exercise 试题 / answer 答案解析。
- `label`：原书题号（"例 1"、"第 3 题"）。
- `content_md`：题干（例题含解析），LaTeX 公式。
- `paired_item_id`：试题 ↔ 答案互相关联。
- `qc_status` / `qc_score`：质检状态与置信分。
- 分类维度（冗余存储，过滤主力）：科目、年级、章节（试卷类为空）、taxonomy（计算/几何/数论/应用/计数/组合，来自目录词表）、tags（倒推法/枚举法/强基/冲奥等，数组）、难度（可空）。
- 回溯维度：物理页码 + 印刷页码。

### item_blocks（区块 ↔ 条目关联）

`(item_id, block_id, role)`，role ∈ stem 题干 / figure 配图·竖式 / solution 解析。
用途：展示回溯、人工复核并排对照、增量重跑（换模型只重跑公式块再更新关联条目）、未来以图搜题取 stem 块。

### item_embeddings（向量）

`vector(1024)`，本地 bge-m3。
**embed_text 显式构造**：科目 + 章节 + 分类 + 标签 + 题干 +（例题附加解析要点）。
理由：题干本身常缺语义（"在方框里填上合适的数字"），必须把分类语义灌进向量；答案不单独建向量，通过 paired_item_id 查询时带出。

## 7. 质量保障与人工复核

### 自动化质检

- **黄金集**：三本书各抽数页共 20~30 页，人工逐块校到全对；每次改流水线跑回归，指标：区块识别准确率、条目拆分准确率、数学内容一致率。
- **条目级置信分**：LaTeX 可编译性、题号连续性、抽样双模型比对 → 高置信直接入库，低置信进复核队列。

### 人工复核工作流

- **进队规则（两条路）**：
  1. 置信分低于阈值（初值 0.8，按抽检结果校准）的条目；
  2. 随机抽检：每本书每批次抽 5% 的高置信条目——没有这个，阈值就是拍脑袋，真实错误率无从得知。
- **复核操作**：每条目显示 裁图（stem/figure/solution）与 content_md 并排，三选一：通过 / 编辑后通过 / 打回并选错误类型。
- **错误分类**（打回必选，指导重跑）：`formula` 公式错 / `structure` 拆分错（漏题、题目合并错）/ `meta` 标签错 / `ocr` 文本错。
- **纠错回流**：打回条目按错误类型重跑对应阶段（formula→③硬区域重解析；structure/meta→④重拆分/重打标）；修正后的条目累积进黄金集，黄金集随使用持续变大。
- **载体**：第一期 CLI 导出复核包（JSONL 清单 + 裁图路径，编辑器里批改后脚本回填）；第三期做本地 web 小工具（FastAPI + 单页，键盘快速操作）。
- **验收指标**（每本书跑完后评估）：黄金集条目级完全一致率 ≥ 95%；抽样错误率 < 5%；未达标则先改对应阶段，再放量下一本。

## 8. 错误处理与断点续跑

- 每阶段状态落库（pending/done/failed），任何阶段可独立重跑。
- 单页/单块失败只记录不中断整轮。
- 裁图等文件以不可变 ID 命名，不随重命名漂移。

## 9. 实施分期

1. **骨架期**：数据模型 + 流水线框架 + 沿用现有 qwen 整页解析接入（端到端跑通）+ 黄金集建立。
2. **精度期**：接入版面分析与分级解析，黄金集回归达标。
3. **检索期**：向量化 + 查询接口（SQL 过滤 + 向量召回混合）+ 复核界面。

## 10. 非目标（YAGNI）

- 以图搜题（未来需要时加 block_embeddings，关联表已留好角色字段）。
- 多用户、权限、Web 服务化。
- 专用向量数据库。
